# SRV-04 — дизайн-записка реализации (2026-11-14, ночная сессия 10)

Задача: batch/cache model properties (P1-4, Q-005; prerequisite SRV-03 закрыт
коммитом c763b66). Authorization: ночной промт владельца
docs/review/continue-prompt-srv03-2026-11-13.md, Этап 2.

## 1. Исходное состояние (HEAD c763b66, поколение 723c8137)

P1-4 (N+1): `ЗначениеРеквизитаМодели` вызывается отдельно на каждую пару
(модель × реквизит) внутри циклов подбора замещений (`ПодобратьЗамещение` —
цикл кандидатов) и расчёта доступности (`ДоступностьМашиныДляСтроки` на
каждую машину через `ДоступностьСтрокиДвумяУровнями`). На реальном расчёте
десятки-сотни однотипных запросов к каталогам моделей АПК.

Используемые реквизиты по каталогам (`ПриоритетРеквизитовЗамещения`):
СХТехники = [КоэффициентПереводаВУЭГА, ШиринаОбработки, ОбъемБункера] +
стартовый МощностьДвигателя; СХОборудования = [ШиринаОбработки];
Автотранспорта = [Грузоподъемность, Вместимость] + МощностьДвигателя;
Прицепов = [Грузоподъемность, Вместимость]. Все существуют в метаданных
живой базы (факт Q-005); отсутствующий реквизит = несовпадение версий АПК.

SRV-03 уже ввёл опциональный параметр-кэш дросселирования ЖР
(`ПредупрежденныеРеквизиты`, голое Соответствие), протянутый от вершин
расчёта. SRV-04 заменяет его на полноценный кэш расчёта.

## 2. Решения

### 2.1 Кэш расчёта — одна структура

`НовыйКэшРасчета()` (Экспорт) → Структура из трёх Соответствий:
- `Модели` — Ссылка → Соответствие(Реквизит → Число): пакетные значения;
- `Предупреждения` — «Каталог.Реквизит» → Истина: дроссель ЖР (наследие
  SRV-03, семантика не меняется — одна запись на пару за расчёт);
- `РеквизитыКаталогов` — «Каталог.Реквизит» → Булево: кэш проверок
  метаданных (`ЕстьРеквизитСправочника` больше не ходит в Метаданные
  на каждую пару).

### 2.2 Пакетная загрузка: одна выборка на каталог

`ПостроитьКэшРеквизитовМоделей(Модели, КэшРасчета = Неопределено)` (Экспорт):
1. Группировка ссылок по каталогам (`ИмяСправникаПоТипуСсылки`, мягкая
   ветка не-ссылок — пропуск с ЖР Предупреждение, как в SRV-03);
2. Состав реквизитов каталога — новый хелпер
   `ПриоритетРеквизитовКаталога(ИмяСправочника)` (извлечён из
   `ПриоритетРеквизитовЗамещения`, который теперь делегирует; сам
   `ПриоритетРеквизитовЗамещения` становится Экспорт — нужен тесту
   эквивалентности);
3. Разделение по метаданным (Q-005 Р1, буквально): существующие — в
   выборку; отсутствующие — ЖР Предупреждение (дроссель, хелпер
   `ПредупредитьОбОтсутствующемРеквизите`) + значение 0 «не заполнено»;
4. Одна выборка на каталог: `ВЫБРАТЬ Спр.Ссылка КАК Модель, Спр.<Р1>,
   ... ИЗ Справочник.<Каталог> КАК Спр ГДЕ Спр.Ссылка В (&Модели)` через
   `ВыполнитьЗапросАПК` (ранняя компиляция, строковые имена таблиц —
   8.5-нюанс соблюдён; виртуальных таблиц нет — plain select каталога);
   сбой выборки = инфраструктура → ЖР Error + исключение (внутри
   `ВыполнитьЗапросАПК`) → остановка расчёта, откат, без частичных
   строк — контракт Q-005 Р1 сохранён буквально;
5. Заполнение кэша: отсутствующие в метаданных реквизиты предзаписаны
   нулями — поштучная семантика «не заполнено» сохранена.
Итого: вместо N×M поштучных запросов — ≤ 1 запроса на участвующий
каталог (обычно 1-2 на расчёт — «одна-две выборки»).

### 2.3 Точки входа

- `РассчитатьДефицит`: кэш строится ПОСЛЕ авторитетных чтений №2
  (пост-блокировочно) из `ТЗПотребность.МодельТехники` +
  `ТЗДоступность.МодельТехники` — значения отражают авторитетное
  состояние; передаётся вниз через `ДоступностьСтрокиДвумяУровнями` →
  `ДоступностьМашиныДляСтроки` → `КоэффициентЗамещения` →
  `РеквизитЗамещения` → `ЗначениеРеквизитаМодели`.
- `ЗаполнитьТЧПланаРабот`: из `Потребность.МодельТехники` +
  `Доступность.Модели.МодельТехники`; передаётся в `ПодобратьЗамещение`.
- `ПодобратьЗамещение` без кэша (тесты, разовые вызовы): создаёт
  `НовыйКэшРасчета()` на вызов — дроссель ЖР работает, батчинга нет,
  поштучная ветка = прежнее поведение.

### 2.4 Поштучная ветка сохранена как эталон и fallback

`ЗначениеРеквизитаМодели(Модель, ИмяРеквизита, КэшРасчета = Неопределено)`:
сначала кэш (модель найдена и реквизит в наборе каталога → значение);
иначе — прежняя поштучная ветка (метаданные с кэшем → дросселированное
ЖР → запрос). Третий параметр меняет тип с Соответствия (SRV-03) на
Структуру-кэш — тест ТестРеквизитМоделиОтсутствуетВМетаданных обновлён
под новый тип (ожидания дросселя прежние: пара фиксируется один раз,
повтор не растит).

### 2.5 Числовая эквивалентность

Пакетная выборка читает те же поля тех же каталогов тем же механизмом
(ВыполнитьЗапросАПК); кэшированное значение = результату поштучного
запроса на тех же данных. Доказательство — новый тест
`ТестПакетныйКэшЭквивалентенПоштучному`: фикстуры в 3 каталогах
(дубликаты в списке моделей допустимы), сравнение каждой пары
модель × реквизит (кэш против поштучно) + `КоэффициентЗамещения` с
кэшем и без = один и тот же К. Существующие 4 теста замещения —
без правок ожиданий (вызовы без кэша = прежняя ветка).

### 2.6 Без третьего состояния

`КоэффициентНеЗадан` не меняется; ЖР Предупреждение — единственная
«видимость» несуществующего реквизита (дроссель при построении кэша
гарантирует одну запись на пару). `В (&Модели)` с массивом ссылок —
стандартный механизм 1С; runtime-проба = первый запуск юнит-теста
(правило двух попыток).

## 3. Тесты

1. `ТестПакетныйКэшЭквивалентенПоштучному` (новый): эквивалентность
   значений по всем парам + эквивалентность коэффициента; кэш содержит
   все модели (дедупликация).
2. `ТестРеквизитМоделиОтсутствуетВМетаданных` (обновление типа
   параметра): ожидания прежние.
3. EXPECTED_TOTAL 28 → 29; раннер +1 обёртка.
4. Регресс: VA 01-09 (05 гоняет полный `РассчитатьДефицит` через UI —
   пакетный путь под нагрузкой), круговая выгрузка v5, остатки.

## 4. Вне области

- `МощностьДвигателяМодели` (мёртвый экспорт) — не трогаем.
- Формирование/СКД/роли — не трогаются.
- Пакетная загрузка «Оборудования» строк потребности — не требуется:
  сцепка не читает реквизиты оборудования (только имена каталогов).

## 5. Вопросы владельцу

Не выявлено: решения Q-005 Р1 и дросселирования (13.11) реализованы
буквально; смена типа параметра кэша — внутренняя (совместимость
вызовов сохранена значением по умолчанию). Дополнительные чтения
каталогов внутри транзакции заменяют собой прежние поштучные чтения
в той же точке — профиль блокировок не меняется.
