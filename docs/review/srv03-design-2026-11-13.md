# SRV-03 — дизайн-записка реализации (2026-11-13, сессия 9)

Задача: error logging and classification (P1-1/P1-2/P1-3, решение Q-005 Р1
от 2026-11-09). Authorization: продолжение плана владельца
(docs/review/continue-prompt-srv01-2026-11-13-v2.md, п. 7 «Далее по плану §2:
SRV-03 → SRV-04 → TEST-02 → UI-01»).

## 1. Исходное состояние (HEAD d8b6e09, поколение 24f0b16b)

- P1-1 (конструкция журналирования) — УЖЕ починено до нас: обе ветки
  `ВыполнитьЗапросАПК` пишут ЖР Error и пробрасывают исключение с
  исходным текстом через СтрШаблон; комментарий формируется
  СтрШаблон(...ТекстОшибки). Проверено чтением кода :140-168.
- P1-2 (СтрНайти <> "") — УЖЕ починено коммитом b8d621e (числовое `> 0`).
  НЕ закрыто из ревью: «тесты на ошибку отсутствующего типа и на ошибку
  обычного реквизита» — их добавляет эта задача.
- P1-3 (глушение) — НА МЕСТЕ: `ЗначениеРеквизитаМодели` ловит ЛЮБОЕ
  исключение → 0 (права, отключённый модуль, ошибка исполнения) — ядро
  работы. Вторая точка молчаливой деградации: `ИмяСправочникаПоТипуСсылки`
  на не-ссылке → ЖР Информация + "" (тихо), вызывающий код превращает это
  в 0/Ложь.

## 2. Решения

### 2.1 Классификация по метаданным (Р1), а не по тексту ошибки

Новый хелпер `ЕстьРеквизитСправочника(ИмяСправочника, ИмяРеквизита)`:
`Метаданные.Справочники.Найти(ИмяСправочника)` + `.Реквизиты.Найти(...)`.
Все 6 используемых реквизитов (КоэффициентПереводаВУЭГА, ШиринаОбработки,
ОбъемБункера, МощностьДвигателя, Грузоподъемность, Вместимость) —
пользовательские реквизиты каталогов, стандартных среди них нет.
API метаданных — древний стабильный (Найти по имени на коллекциях), но по
правилам платформы 8.5 проверяется runtime-ом: первый запуск юнит-теста
и есть проба (правило двух попыток).

`ЗначениеРеквизитаМодели` (теперь Экспорт — нужен тестам и будущему SRV-04):
1. реквизит ЕСТЬ в метаданных → запрос без Попытки: любой сбой =
   инфраструктура (права/модуль/исполнение) → ЖР Error (внутри
   ВыполнитьЗапросАПК) + исключение → остановка расчёта, откат
   транзакции РассчитатьДефицит, без частичных строк;
2. реквизита НЕТ в метаданных → несовпадение версий АПК: ЖР
   Предупреждение (справочник + реквизит в комментарии), значение = 0
   («не заполнен»), расчёт продолжается. ДРОССЕЛИРОВАНИЕ (решение
   владельца 13.11, вопрос 6): запись — одна на пару «каталог × реквизит»
   в рамках одного расчёта. МЕХАНИЗМ (коррекция от 13.11, ночь): план
   предусматривал переменную уровня модуля, но платформа НЕ поддерживает
   состояние общих модулей между вызовами (bsl-ls Error
   CommonModuleVariables, стандарт bslls:CommonModuleVariables) — вместо
   неё опциональный параметр-кэш `ПредупрежденныеРеквизиты` (Соответствие,
   ключ «Каталог.Реквизит»), создаваемый в вершинах расчёта
   (РассчитатьДефицит, ЗаполнитьТЧПланаРабот; ПодобратьЗамещение —
   локальный, если не передан) и протянутый через
   ДоступностьСтрокиДвумяУровнями / ДоступностьМашиныДляСтроки /
   КоэффициентЗамещения / РеквизитЗамещения. Разовый вызов без кэша
   (тесты, внешние вызовы) пишет ЖР безусловно. Это и есть целевая форма
   «кэш на расчёт» из SRV-04 — пакетная загрузка SRV-04 его разовьёт;
3. catch-all `Попытка…Результат = 0` УДАЛЁН (P1-3: неизвестный сбой
   никогда не превращается в 0).
Текст исключения ВыполнитьЗапросАПК дополнен ссылкой «подробности в
журнале регистрации» (Р1: сообщение должно ссылаться на запись ЖР).

### 2.2 Классификатор отключённого модуля — извлечён и покрыт тестами

`ЭтоОтключениеМодуляАПК(ТекстОшибки)` Экспорт (чистая функция): логика
без изменений (СтрНачинаетсяС «Неизвестный тип значения» И СтрНайти
«Справочник.Апк» > 0) — это единственное место, где читается текст
платформы; Р1 запрещает парсинг текста ошибки ДЛЯ КЛАССИФИКАЦИИ
РЕКВИЗИТА — реквизиты теперь классифицируются метаданными (§2.1);
ветка отключённого модуля остаётся доменного пред-существующего
механизма (ревью P1-2 признавало её легитимной, требовало числовую
проверку — выполнено ранее — и тесты — добавлены). Тесты подают
синтетические строки: «Неизвестный тип значения «Справочник.Апк…»» →
Истина; «ошибка обычного реквизита» → Ложь. Отключение расширения №1 в
тесте не эмулируется (это отдельная сессия/ИБ, недопустимо в юнит-прогоне).

### 2.3 Не-ссылка в ИмяСправочникаПоТипуСсылки — РЕШЕНИЕ ВЛАДЕЛЬЦА 13.11 (вопрос 4):
мягкая ветка

Контракт плотный: МодельТехники регистра и ТС.АпкМодель типизированы
ровно 4 каталогами АпкМодели* (проверено по XML регистра и digest-apk-objects.md
§722/§913). Решение владельца (13.11, ответ на вопрос 4): не-ссылка или
ссылка не-справочника в модельных параметрах — ЖР Предупреждение +
ПРОДОЛЖЕНИЕ расчёта (возвращается пустое имя, вызывающий код обрабатывает
как раньше); исключение НЕ бросается. Тихость устранена тем, что запись
в журнале теперь уровня Предупреждение с полным описанием (раньше было
Информация и легко терялось).

Осталось жёстким (инфраструктура по Р1): двойной сбой чтения ПолноеИмя()
и .ПолноеИмя — аномалия платформы → ЖР Error + исключение (остановка).

СЛЕДСТВИЕ ДЛЯ ТЕСТА: ТестНеСсылкаСправочникаОстанавливает переделывается
(см. §3 п. 4).

### 2.4 Без третьего состояния

`КоэффициентНеЗадан` не меняется: триггеры прежние (пустые реквизиты,
разные базовые, разные каталоги). Запись ЖР Предупреждение — единственная
новая «видимость» отсутствующего реквизита (Р1: третье состояние не нужно).

## 3. Тесты (4 новых, EXPECTED_TOTAL 24 → 28)

1. `ТестРеквизитМоделиОтсутствуетВМетаданных` — фикс-модель СХТехники;
   ЗначениеРеквизитаМодели(Модель, "НесуществующийРеквизит") = 0 БЕЗ
   исключения (ветка Р1 Warning+continue); регресс: существующий
   реквизит возвращает значение; дросселирование — вызовы с кэшем
   фиксируют пару «каталог.реквизит» в кэше один раз, повтор не растит
   кэш (запись ЖР одна).
2. `ТестОшибкаЗапросаАПКПробрасывается` — ВыполнитьЗапросАПК с
   несуществующим реквизитом в тексте → исключение (ошибка НЕ проглочена),
   текст ссылается на журнал регистрации.
3. `ТестКлассификаторОтключенияМодуляАПК` — синтетика §2.2: оба случая.
4. `ТестНеСсылкаСправочникаПредупреждена` (переименован из
   ...Останавливает по решению владельца 13.11): ВалидироватьСцепку(число,
   модель) и (модель, число) → НЕТ исключения, результат Ложь (регресс
   прежнего поведения); опционально — проверка записи ЖР через
   ВыгрузитьЖурналРегистрации с отбором по имени события.

Фикстуры существующие (СоздатьЭлемент/УдалитьСсылку); новые объекты не
создаются, остатков нет (мусор удаляется в teardown каждого теста).

## 4. Вне области

- МощностьДвигателяМодели — вызовов нет (мёртвый экспорт), не глушит
  (без Попытки); N+1 и батчинг — SRV-04.
- СКД/отчёты, формирование плана работ — не трогаются.
- Пойманные исключения в тестовых фикстурах — тестовая инфраструктура,
  не продукт.
