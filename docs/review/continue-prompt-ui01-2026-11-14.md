## КЛЮЧЕВЫЕ ГРАБЛИ (выучены в этом прогоне, не повторять)

1. **Грабля №3 — загрузка расширения.** Пакетная загрузка из файлов
   оставляет расширение «ожидающим применения»; пакетное обновление
   конфигурации базы его НЕ применяет. Применяет только агент
   конфигуратора, и агент ДОЛЖЕН быть перезапущен ПОСЛЕ загрузки.
   Канон: **загрузка → `taskkill 1cv8.exe` → `designer_agent.py start`
   → apply → genid**. Признак успеха — строка «Создано поколение
   расширения конфигурации: <хэш>». Без неё всё остальное врёт.
2. **CRLF.** Модули объекта (обработки, регистры) — CRLF, общие модули
   и модули форм — LF. Перед записью скрипт должен определить перевод
   строки по исходному файлу и писать тем же.
3. **Якоря.** Перед `replace` — `assert t.count(anchor) == 1` и печать
   количества. Дублирующийся якорь = скрипт падает ДО записи (как
   случилось с `ui01_moment_api.py`). Никогда не писать «наугад».
4. **Скрипт-вставка функции в модуль формы** должна ставить блок ПЕРЕД
   заголовком процедуры-обработчика, а не после него: иначе текст
   функции оказывается внутри тела процедуры (так были получены три
   ошибки разбора в первой попытке; лечится `git checkout -- <папка>`).
5. **Статический контроль** после правок: `scripts/bsl_balance_check.py
   src/cfe/ПланированиеТехникиАПК` (ожидание `checked=14 broken=0`),
   `scripts/pre_load_validate.py` (27 файлов), затем MCP `bsl-ls`
   `bsl_analyze` по изменённым каталогам: **0 Errors обязателен**,
   предупреждения не должны превысить базовые 36 (подсказки 17).
6. **Кириллица и вывод.** Лог прогона юнитов пишется в потере
   кодировки — имена тестов в нём нечитаемы. Для разбора — COM-проба
   (`tmp/t02_probe_skip.py` как шаблон) или сверка по числу строк.
7. **Очистка по маскам** в тестах исключает стабильный набор данных
