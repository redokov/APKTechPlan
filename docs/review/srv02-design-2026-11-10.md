## 2. Calculation model (РассчитатьДефицит rewrite)

Per demand row (org O, subdiv P, model M, category V, shifts S, days D, shifts/day Sh):
- Level 1 (A2): machines with slice (org=O AND subdiv=P), category V, model match
  (exact for Автотранспорт/Оборудование/Прицеп; СХТехника keeps substitution by
  converted attribute with КоэффициентНеЗадан semantics). Machine capacity =
  D × Sh shifts. Available1 = sum over matching distinct machines.
  ShortageAfterOwn = max(0, S − Available1).
- Level 2 (B2, cross-org pool): remaining scenario machines of category V whose
  attachment (org,subdiv) ≠ (O,P) or missing. Coverage tracked PER SOURCE attachment
  (org, subdiv); each source contributes up to its machines' capacity (model match
  rules as level 1). FinalDeficit = max(0, ShortageAfterOwn − Available2).
- Per-row independence (no cross-row machine consumption) — same as the current
  implementation where each demand row sees full availability; Q-002 did not decide
  a bin-packing order (OWNER-REVIEW note, not a semantic change).
- ПланТехресурсовОтсутствует flag (existing resource, TEST-01-tested): now means
  "no level-1 machines attached to the demand (O,P)" — nearest equivalent of the old
  "no plan rows for the subdivision" (OWNER-REVIEW).
- Filters of the calculation form (Организация/Подразделение/ВидТехники) scope the
  DEMAND rows (as today); the pool stays cross-org per B2. Level-1 matching uses
  slice values (per requirements.md note), never document headers.

## 3. Register Тх_ДефицитТехники (CFE object, extended)

- New dimensions: ИсточникОрганизации (Справочник.Организации, empty allowed),
  ИсточникПодразделения (Справочник.СтруктураПредприятия, empty allowed).
- New resources: НехватаетПослеСвоихСмен (10.2), ПеремещеноСмен (10.2).
- Row kinds in the same register, distinguished by the source dimensions:
  - deficit row: source dims empty; carries ПотребностьСмен, ДоступноСмен,
    НехватаетПослеСвоихСмен, НехватаетСмен (= final deficit), ДнейПериода, СменВДень,
    КоэффициентНеЗадан, ПланТехресурсовОтсутствует;
  - move row: source dims = attachment of the covering machines; ПеремещеноСмен =
    shifts moved from that attachment to the demand (O,P); other resources carry the
    demand-row context (ПотребностьСмен of the row, zeros elsewhere).
- Rationale: Q-002 requires the register to store the TWO numbers and the report to
  show required moves "(attachment org/subdivision -> demand org/subdivision)";
  persisting moves as source-dimensioned rows is the minimal way to render both ends
  of the arrow without new metadata objects.

  СменВДень)); distinct physical ТС of the matching model are picked (СХТехника may

- The result structure keeps the today contract: Строк, Смен, Часов, Замещено,

  structure and the filled ТС rows. The per-row Комментарий ("замещение: ...") is no

- 'Перезаполнить текущий' refills an existing АпкПланТехническихРесурсов (clears the
