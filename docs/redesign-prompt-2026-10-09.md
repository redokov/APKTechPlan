## 5. Процесс (SDD-скиллы, каждый — читать перед применением)

1. `sdd-idea` — зафиксировать идею перепроектирования, ЗАДАТЬ ПОЛЬЗОВАТЕЛЮ вопросы (§10 + возникшие).
2. `sdd-prd` — `.ai/sdd/specs/002-…/requirements.md` (FR/EARS, NFR).
3. `sdd-spec` — design.md: структура объектов, типы реквизитов, механизм формирования из техкарт
   (какие регистры читать, формулы мощности/ширины), формы, роли, сценарии тестов.
4. `sdd-tasks` — tasks.md с зависимостями и гейтами.
5. `sdd-exec` — реализация задач; после КАЖДОЙ задачи: pre_load_validate → bsl-ls (MCP, изменённые каталоги,
   «0 файлов» = НЕ выполнено) → db-load-xml Full -UpdateDB → **прочитать свежий load_log** (см. §9) →
   при структурных изменениях: kill 1cv8* → designer_agent apply (создаёт генерацию; batch НЕ создаёт) →
   прогон VA. Коммит после каждой зелёной задачи + запись в `heartbeat/night.log`.
6. `sdd-review` — ревью против requirements/design перед финальным «готово».

## 7. Субагенты (local_qwen от вормсофт) — правила

- Модель: `local_qwen` (параметр `model` при вызове Agent). Промт субагента САМОДОСТАТОЧЕН — он не видит
  контекст главной сессии. ЗАПУСКАТЬ СТРОГО ПОСЛЕДОВАТЕЛЬНО, ПО ОДНОЙ, НЕ ПАРАЛЛЕЛИТЬ.
- Субагент изолирован и возвращает в основной контекст ТОЛЬКО результат (вердикт/дифф/фрагмент/список ошибок),
  без листингов и чтения больших файлов.
- Делегируй: генерацию черновиков XML/BSL/feature-фрагментов по точной спецификации (пути, имена, типы, образцы);
  независимый разбор одного файла/объекта; аудит по чек-листу; формулировки Gherkin по скиллу vanessa-automation;
  исследование APKModSrc по конкретному вопросу (cf-explorer/Explore).
- НЕ делегируй: загрузки/дампы/прогоны VA/коммиты; решения о структуре метаданных; работу с кириллицей в argv
  команд; чтение cp1251-логов; верификационные работы.
- Напоминай каждому: файлы utf-8-sig + CRLF (newline=''), кириллицу в файлы — только python с явным encoding;
  вернуть только краткий результат.

## 8. Факты платформы 8.5.4.1683 / инфраструктуры (НЕ переоткрывать — каждое стоило 15–60 мин)

- **FillValue на реквизитах ТЧ (CommonAttribute) в расширении НЕВОЗМОЖЕН** — отвергается загрузкой
  («Свойство FillValue не входит в состав объекта метаданных Attribute»); на реквизитах ШАПКИ возможен.
  Дефолты новой строки ТЧ — только формой: событие таблицы `BeforeAddRow` (перед началом добавления),
  сигнатура обычной таблицы `(Элемент, Отказ, Копирование)`, паттерн «Отказ=Истина + программное Добавить()
  с дефолтами» (реализовано в Тх_ФормаДокумента, см. ШАГ 0). События «после добавления строки» у таблицы НЕТ
  (проверено по 10964 формам ERPsrc; post-add события не существует).
- Загрузка конфигурации из XML НЕ атомарна: невалидное свойство пропускается с ошибкой в логе, объект грузится.
- Batch `/UpdateDBCfg -Extension` НЕ создаёт новую генерацию — реальный apply: Designer AgentMode SSH
  (designer_agent.py, рестарт агента перед каждым apply). Privileged=true в модулях расширения запрещён
  (batch молча exit 0). Тх_ТехникаСервер: Privileged=false + ExternalConnection=true.
- Кэш rphost: при структурных изменениях kill 1cv8c/1cv8 → повторный `scripts/b6_updatedbcfg.py` → при
  необходимости пауза (по указанию пользователя пауза после обновления конфигурации БД НЕ нужна — не вставлять
  sleep автоматически).
- БСП-пересчёт после UpdateDBCfg сбрасывает роли ИБ: перед каждым VA-проном `va_assign_roles_direct.py` (или
  ensure_roles внутри run_va_feature.py — работает при PYTHONIOENCODING=utf-8).
- 8.5 клиентский код: `Перечисления` недоступны; прямые вызовы серверных общих модулей из клиента запрещены →
  `&НаСервереБезКонтекста`/`&НаСервере` методы формы. `Строка(ТипЗнч())` возвращает синоним типа, не
  'СправочникСсылка.X' — парсить `Метаданные().ПолноеИмя` (ПолноеИмя() в 8.5 — метод). Виртуальные таблицы
  запросов — dot-синтаксис + суффикс Oborot. ValueTable.Найти() возвращает строку, не индекс.
- НТТ/Vanessa: ссылочные поля — только «ввожу текст 'X'» (dropdown-выбор ненадёжен); Enum — надёжен;
  generic-поля непроходимы (после ретайпинга это уйдёт); проверки отказов записи — серверно
  (ВызватьИсключение), «в логе сообщений TestClient» сломан; кавычки в feature-таблицах удваивать;
  «перехожу к строке» надёжен по колонке 'Номер'; кнопки авто-панели: ФормаСоздать/ФормаЗаписать/ФормаПровестиИЗакрыть;
  собственные команды — явная `<Button>` с `<CommandName>Form.Command.X</CommandName>`.
- Комментарии `#` ВНУТРИ таблицы кода VA парсятся как ряды — не вставлять; BSL-комментарий в коде — `//`,
  каждая строка таблицы обязана начинаться И заканчиваться `|`.
- Модели форм: Tables id=25 (ОсновнаяТехника)/58 (Оборудование)/91 (Автотранспорт); колонки
  ТранспортноеСредство, МодельТехники, Принят (CheckBoxField), Количество, Комментарий; ХозНомер — вычисляемая
  (AdditionalColumns), в документе не хранится. Events таблицы вставляются после `</SearchControlAddition>`
  перед `<ChildItems>` (7 табов).
- bsl-ls false positives: UnusedLocalMethod для обработчиков форм, QueryParseError на 8.5 dot-синтаксисе
  виртуальных таблиц — известные (docs/bsl-ls-false-positives.md), не чинить.
- НЕ трогать расширение «Расширение_АПК» (чужое) и VAExtension.
- COM: `XMLСтрока()` для GUID; `НайтиПоНаименованию` для пустой ссылки = нулевой GUID.
- НЕ добавлять -y/--yes к деструктивным операциям; «***» в выводе — редакция, не эхо.
- Открытая проблема прошлого прогона (может всплыть): команда «Планы технических ресурсов» не найдена в
  панели раздела при VA-навигации (метаданные/права/CommandInterface проверены и корректны; возможно,
  вопрос к фактической видимости — проверить на обычном пользователе при ретесте).

## 11. Anti-patterns

- Не переоткрывать факты §8 — каждый стоил 15–60 минут отладки.
- Не вставлять \ufeff руками (двойной BOM) — только utf-8-sig через python.
- Не читать большие файлы целиком; grep -n первым; bash-вывод с кириллицей — в файл и читать read'ом.
- Не делегировать субагентам прогоны/загрузки/коммиты/кириллицу в argv.
- Не тестировать права на админских пользователях (ПолныеПрава — маскировка).
- Не продолжать старую спеку 001 как истину — она устарела в части форм/типов; использовать как справочник фактов.
- Вставка пауз/снов «на всякий случай» — запрещена (см. §8, указание пользователя).
