## §2. Критичные проблемы (P0)

### 2.1 Потеря данных при параллельных расчётах дефицита
- **Файлы:** `Тх_ТехникаСервер/Module.bsl`, `Тх_ДефицитТехники.xml`
- **Суть:** `РассчитатьДефицит` делает `Записать(Истина)`/`Записать(Ложь)` по отбору без `БлокировкаДанных`. При двух параллельных запусках вторая транзакция уничтожает записи первой → гонка.
- **Дополнительно (BSL-линза):** транзакция без явного уровня изоляции; на кластере возможны пересечения.
- **Дополнительно (архитектура):** регистр Independent, DataLockControlMode=Managed не спасает от read-modify-write.

### 2.2 Семантика проведения подменена флагом
- **Файл:** `Тх_ПланТехническихРесурсов/ObjectModule.bsl`
- **Суть:** `Posting=Allow`, но `RegisterRecords` пуст. Отмена проведения / правка проведённого / удаление не пересчитывают `Тх_ДефицитТехники` → производные данные тихо устаревают.

### 2.3 Тестовая достоверность нарушена (BSL-линза)
- **Файл:** `Тх_Тесты/Module.bsl`
- **Суть:** SKIP засчитывается как PASS — `СообщитьПропуск()` лишь печатает, тест возвращает `Истина`. 8 из 20 тестов тихо пропускаются на пустой базе → CI даёт 20/20 при фактическом 12/20.

### 2.4 Утечки данных в тестах (тестовая линза — 8 пунктов)
- **Файл:** `Тх_Тесты/Module.bsl`
- **Суть:** `СоздатьЭлемент` присваивает ссылку до `Записать()` → при сбое объект остаётся, но не удаляется; `УдалитьСсылку` удаляет, но не отменяет проведение документа; в `ТестНеПринятыеТСИсключены` (line 501) при провале создания ТС флаг `ТССоздана=Ложь` и очистка в finally пропускается → ТС утекают в БД.
- **VA-тесты:** фичи 03, 04 — документы остаются в БД после прогона; 08 — планы распределения удаляются по широкому отбору (сценарий НИВА/Основной), а не по уникальному идентификатору.

### 2.5 Тестовый код в прод-CFE с `ExternalConnection=true`
- **Файлы:** `Тх_Тесты.xml`, `Тх_РаннерТестов.xml`, `Configuration.xml`
- **Суть:** модули Тх_Тесты (20 экспортных `Тест*`) + раннер — часть продуктового расширения, доступны из COM. `DefaultRoles` содержит `Тх_Редактирование` → новые пользователи получают запись по умолчанию.

### 2.6 Правовой контур сломан
- **Файлы:** `Тх_Чтение/Ext/Rights.xml`, `Configuration.xml`
- **Суть:** роль «Чтение» имеет `Use` на записывающих обработках (`Тх_РасчетДефицита`, `Тх_ФормированиеПланаРаботТехники`), но нет прав записи → ошибка прав при запуске; `InputByString` избыточен.

### 2.7 Устаревшие VA-фичи (тестовая линза)
- **Файлы:** `tests/vanessa/00-diag-*` (5 шт.), `08-polzovatel-bez-rolej-ne-vidit.feature`
- **Суть:** ссылаются на удалённый регистр `Тх_КоэффициентыПересчетаРабот` (FR-005) и шаги VA-single, которых не существует → гарантированные падения при прогоне; фича 08 помечена «ЗАМЕНЕН», но в наборе с несуществующими шагами; механизмов тегирования/выключения нет.

### 2.8 Инвертированная проверка в VA-фичах
- **Файл:** `05-raschet-deficita-i-filtry-otcheta.feature`
- **Суть:** `Выборка.Количество()` до `Следующий()` — всегда 0, проверка либо всегда падает, либо ничего не проверяет.

### 2.9 Ложная тревога линзы архитектуры — зафиксирована для исправления методики
- **Файл:** `Configuration.xml` (декларирует 12 объектов)
- **Суть:** линза объявила объекты «сиротами/пустыми каркасами», потому что BSL-модули лежат отдельно в `Ext/*.bsl` (нормальный паттерн CFE). **Подтверждено:** `<Module>` в XML нет, но есть `Ext/*.bsl`; нет пустых каталогов, нет пустых XML. Требуется: в AGENTS.md добавить, что при CFE проверять наличие `Ext/` и `<Module>` как взаимодополняющих источников.

## §3. Серьёзные проблемы (P1)

### 3.1 Производительность расчёта (BSL-линза)
- **Файл:** `Тх_ТехникаСервер/Module.bsl`
- **Суть:** `РассчитатьДефицит → ДоступноСменСтроки → КоэффициентЗамещения → ЗначениеРеквизитаМодели` = цикл по N×M парам × до 8 рантайм-запросов = до 16 000 запросов на 100×20.
- **Дополнительно (архитектура):** `ПодобратьЗамещение` перебирает все модели, `ДоступныеМоделиПодразделения` — ЛЕВОЕ СОЕДИНЕНИЕ с ТЧ; `МощностьДвигателяМодели` — отдельный запрос на каждый вызов.
- **Дополнительно (тестовая):** `НайтиПервыйЭлемент` — отдельный рантайм-запрос на каждый каталог.

### 3.2 Запросы без периода (BSL-линза)
- **Файл:** `Тх_ТехникаСервер/Module.bsl`
- **Суть:** `Обороты()` без аргументов периода — агрегация по всему регистру, фильтрация в ГДЕ. 4 места (588, 603, 860, 872).

### 3.3 Неконсистентность отбора по подразделению (BSL-линза + архитектура)
- **Файл:** `Тх_ТехникаСервер/Module.bsl`
- **Суть:** `ЗапросПотребности` — точное равенство, `ПотребностьПоТехкартам`/`ДоступныеМоделиПодразделения` — В ИЕРАРХИИ → для групповых подразделений несопоставимые цифры.
- **Дополнительно (BSL-линза):** в `ЗапросПотребности` подразделение отбирается точным равенством, хотя в других функциях ИЕРАРХИИ → потребность по групповому подразделению занижена.

### 3.4 Ошибки рантайм-запросов маскируются
- **Файл:** `Тх_ТехникаСервер/Module.bsl`
- **Суть:** `ВыполнитьЗапросАПК` ловит ВСЕ исключения и выбрасывает «Модуль АПК отключён: ...» — синтаксис, права, отсутствие реквизита неотличимы от отключённого модуля.
- **Дополнительно (архитектура):** `ЗначениеРеквизитаМодели` глотает исключения → 0 вместо диагностики; `TODO-VERIFY` в `МощностьДвигателяМодели` — имя реквизита для остальных каталогов не проверено.

### 3.5 Привилегированность модуля не настроена
- **Файлы:** `Тх_ТехникаСервер/Module.bsl`, `Тх_ТехникаСервер.xml`
- **Суть:** комментарий «привилегированный» vs `<Privileged>false</Privileged>` — рантайм-запросы к АПК могут падать на «Недостаточно прав» у обычного пользователя.

### 3.6 Отсутствие проверки прав
- **Файл:** `Тх_ТехникаСервер/Module.bsl`
- **Суть:** публичные серверные функции `ЗапросПотребности`/`ЗапросДоступности`/`ПотребностьПоТехкартам` не проверяют права на сценарий.

### 3.7 Тестовые данные по общим данным (тестовая линза — 13 пунктов)
- **Файл:** `Тх_Тесты/Module.bsl`
- **Суть:** неизолированные тесты (13 категорий): детерминированность (тесты по «первым найденным» данным реального сценария), скриншотные паузы (25 сек на 00-diag-choiceshot), VA-скрипты пишут в общую БД без транзакционного отката, 03/04/08 не удаляют созданные документы, 08 удаляет по широкому отбору.

### 3.8 Зеркальные копии формул (BSL-линза + архитектура)
- **Файлы:** `Тх_Тесты/Module.bsl`, `Тх_ТехникаСервер/Module.bsl`
- **Суть:** `ДоступноСменКонтракт` — зеркало приватной `ДоступноСменСтроки`; при разбеге тесты «зеленеют» на неверном поведении, контракт TD-004 нарушается.

## §8. Методологические выводы (внесены в AGENTS.md)

1. **Перед запуском агентов/оркестратора — читать документацию pi** (`docs/`). Неподготовленный скрипт = неправильный runtime (JS в Python, ESM `require` не работает).
2. **Модельный конфиг — проверять прежде чем запускать:** `model: "anthropic/claude-opus-4.6"` без префикса резолвился в провайдера `bothub` (отрицательный баланс → 403). В `erpband` модель доступна только как `erpband/anthropic/claude-opus-4.6` (предварительно зарегистрирована в `models.json`).
3. **Проверять баланс провайдера** перед запуском (раннее предупреждение, не 403 посреди задачи).
4. **Verify bytes, not display** — перед заявлением о повреждении: декодировать UTF-8, посчитать структуру (функции/строки), кросс-валидировать 2+ способами.
5. **После завершения workflow/агента — обходить ВСЕ артефакты в `tasks/`**, включая `*.workflow.jsonl` — там часто есть данные, которых нет в `*.output`.
6. **Кириллица + Python на Windows:** всегда `PYTHONIOENCODING=utf-8` или shell-утилиты (cut/tail/grep) вместо Python.
7. **bash и Python резолвят `/tmp/` по-разному** — использовать shell-утилиты для чтения логов.
8. **Субагентам — жёсткие лимиты:** max_turns, лимит инструментов, формат вывода через `schema`, stop-condition. Иначе — 49 минут и 489K токенов впустую.
9. **CFE-паттерн:** при проверке XML учитывать, что модули лежат отдельно в `Ext/*.bsl` — это не сиротство.
