# Решение владельца: источник доступности — регистр АпкИсторияТранспортныхСредств

**Дата:** 10.11.2026 (сессия 4, по ходу ремедиации SRV-02 / spec-003)
**Статус:** принято владельцем, к реализации.
**Заменяет:** часть контракта доступности SRV-02 (design §4.7, карта T8), где пул ТС собирался
из табличных частей проведённых Документ.АпкПланТехническихРесурсов.

## Содержание решения (дословно от владельца)

1. **Если ТС есть в регистре АпкИсторияТранспортныхСредств и у него Исправно = Истина — оно доступно.**
2. **На текущем этапе данные документа АпкПланТехническихРесурсов не рассматриваем совсем** (как источник
   доступности; чтение из него исключается).

## Проверенные факты (пробы внешним соединением к dev_erpapk_demo, 10.11.2026, scripts/probe_istok_slice.py)

- Регистр АпкИсторияТранспортныхСредств — периодический; измерение: ТранспортноеСредство.
- Ресурсы: Документ, Организация, **ЭксплуатирующеПодразделение** (двойное «е»), ПодразделениеЗатрат,
  ЦеховаяКладовая, ОсновноеСредство, ПравоСобственности, Арендатор, Арендодатель, **Исправно**.
- СрезПоследних(&ДатаСреза) отдаёт колонки: Период, ТранспортноеСредство, Документ, Организация,
  ЭксплуатирующеПодразделение, …, Исправно — то есть ОДИН срез даёт и доступность (Исправно),
  и приписку (Организация + ЭксплуатирующеПодразделение). Роль регистра упрощается до единственного
  источника.
- На 31.12.2015 в срезе 118 ТС (демо-данные); записей по тестовым ТХТС* НЕТ (0) — тестовые фикстуры
  историй не создают. Следствие: все сетапы (юнит и VA), строившие доступность проведёнными планами,
  заменяются созданием записей регистра с Исправно = Истина (и припиской, где сценарий её проверяет).

## Последствия для кода (Тх_ТехникаСервер)

1. `ЗапросДоступности`: пул = ВЫБРАТЬ из СрезПоследних(&ДатаСреза) ГДЕ Исправно (по последней записи
   каждого ТС: сломанное раньше и починенное позже — исправно). Табличные части планов больше не читаются.
   Модель техники — как раньше, через справочник ТранспортныеСредства (АпкМодель).
2. Вид техники строки пула: раньше — литерал по происхождению (табличная часть плана); теперь —
   из справочника ТранспортныеСредства, реквизит **АпкТипТС** (тип АпкТипыТС: СХТехника/Автотранспорт/
   СХОборудование/Прицеп — точное соответствие сверить пробой при реализации; реквизит подтверждён
   в метаданных справочника).
3. `ПланОтсутствует` = в срезе нет ни одного исправного ТС (новая семантика; прежняя — «нет проведённых
   планов сценария»).
4. Дата среза: ветка «МАКСИМУМ(Дата) проведённых планов» (хотфиксы 2+3 сессии 1–2) УДАЛЯЕТСЯ вместе с
   чтением планов. Новое умолчание (предложение, подтвердить при реализации): ДатаСреза = ДатаНачала
   периода из параметров; если не задана — ТекущаяДатаСеанса. Защита «Если НЕ ЗначениеЗаполнено(ДатаСреза)
   → Дата(1,1,1)» сохраняется как пост-защита параметра среза.
5. Уровень 1/уровень 2 (приписка против общего пула) — без изменений логики, но оба уровня теперь
   черпаются из одного среза; ТС без записи в регистре больше НЕ существует для пула вовсе
   (раньше «ТС без истории — в общем пуле» — теперь таких ТС в пуле просто нет).

## Открытый вопрос (подтвердить у владельца до реализации)

Формирование плана работ сейчас СОЗДАЁТ Документ.АпкПланТехническихРесурсов как свой ВЫХОД
(ретаргет Q-002). Решение владельца сформулировано про ДАННЫЕ документа как ИСТОЧНИК (чтение).
По умолчанию принимаем: выход формирования не меняется (документ создаётся, его данные ничем
не читаются). Если владелец имеет в виду и отказ от записи — формирование теряет целевой объект,
состав SRV-02 меняется — требуется явное подтверждение.
