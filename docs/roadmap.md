## Релиз 2 — «Точность расчёта»

Уточнение модели потребности; всё подготовлено дизайн-решениями релиза 1.

**Функционал:**
1. Учёт сменной нормы выработки — расчёт смен как `ОбъёмРабот / СменнаяНормаВыработки`
   (design 002, FAQ Q4).
2. Переключатель варианта плана Мин / Вер / Макс — сейчас читается только `*_Вер`
   (TD-006 trade-off).
3. Автозаполнение ТЧ «Оборудование» — единственная ТЧ без автозаполнения (FAQ Q1).
4. Флаг «включать опциональные работы» (FAQ Q3 — сейчас отдаётся типовой логике).

**Решения:**
- Доработка запроса `Тх_ФормированиеПланаРаботТехники`: три регистра оборотов
  (`*_Мин/_Вер/_Макс`) + `СменнаяНормаВыработки` из характеристик видов работ.
- Реквизит-переключатель на форме обработки + отбор СКД отчёта.
- Новых метаданных нет — только код и формы. Низкий риск.

## Релиз 3 — «Календарь доступности парка»

Проблема: доступность сейчас — «подразделению распределено N единиц модели».
Реальность: ремонты, техосмотры, пересечение сроков работ между полями; дефицит
считается в среднем за период, а не по датам.

**Функционал:**
1. Временная развёртка дефицита: расчёт по окнам (неделя/декада), учёт пересечения
   сроков работ между полями.
2. Занятость и простои ТС: ремонты, техосмотры снижают доступность в конкретные даты.
3. Детализация до госномеров: «Т-150 №а123вс — занят 12–16.05» вместо «модель — 3 ед.»
4. Отчёт-диаграмма Ганта загрузки моделей/ТС по периодам.

**Решения:**
- Регистр сведений «Занятость ТС» (период, ТС, поле/работа) + регистр
  «Простои/Ремонты ТС» (ручной ввод; позже автозаполнение из документов АПК).
- Переработка ядра расчёта: от «модель × период» к матрице «модель × ТС × окно» —
  крупнейшее изменение ядра, поэтому отдельный релиз.
- Гант — СКД с диаграммой или печатная форма; без заимствования типовых форм.
- Снятие ограничения TD-007: чтение `АпкИсторияТС`.

## Релиз 4 — «Межхозяйственные переброски»

Roadmap-пункт релиза 1 (design 002, FAQ Q9): предложения замен дефицитной модели
техникой других подразделений/хозяйств холдинга.

**Функционал:**
1. Поиск кандидатов-замен по всему парку холдинга.
2. Ранжирование: коэффициент замещения × стоимость переброски (своим ходом /
   трал + спецразрешения).
3. Колонка «Предложение из другого подразделения» в документе «Потребность
   в технике» + суммарная стоимость закрытия дефицита.

**Решения:**
- Справочник «Правила переброски»: пары подразделений, расстояние, тарифы
  (руб/км своим ходом, трал, разрешения) — ручное ведение, без GPS.
- Второй проход расчёта по чужим паркам (`АпкПланТехническихРесурсов` всех
  подразделений).
- Новая роль «Тх_МежХозяйственныйОбзор»: чтение чужих парков поднимает вопрос RLS
  (в релизе 1 RLS не вводился — здесь станет нужен).

## Релиз 5 — «План-факт и диспетчеризация»

Замыкание цикла управления: дефицит посчитан — а что дальше?

**Функционал:**
1. План-фактный анализ: потребность vs факт из путевых/учётных листов тракториста
   и путевых листов автотранспорта (типовой факт главы 1 АПК).
2. Отчёт «Исполнение плана работ техники»: план смен/часов vs факт, % исполнения,
   какие дефицитные позиции реально закрыты.
3. Уведомления за N дней до периода работ о незакрытом дефиците; эскалация по срокам.

**Решения:**
- Чтение фактических регистров АПК по путевым листам (источники уточнить через
  rlm-tools-bsl по APKModSrc — как для оборотов в спеке 002).
- Регламентное задание сверки план/факт в расширении + БСП «Центр уведомлений»
  (штатный механизм, без модификации конфигурации).
- Отчёт — второй вариант СКД существующего отчёта или отдельный.

## Релиз 6 — «Экономика дефицита и мониторинг» (опционально, по спросу)

**Функционал:**
1. Стоимость закрытия дефицита: аренда vs переброска vs покупка — сравнение сценариев
   в деньгах.
2. Перенос в бюджетирование: типовые регистр «Правила получения данных для
   бюджетирования» и документ «Трансляция результатов в бюджетирование» — выгрузка
   плановой потребности в статьях затрат (ГСМ, зарплата механизаторов, аренда).
3. Интеграция с ГЛОНАСС-платформами мониторинга: фактические моточасы и занятость →
   в регистр занятости релиза 3 автоматически.

**Решения:**
- HTTP-сервис в расширении + XDTO-пакеты для приёма данных мониторинга
  (или внешний источник данных).
- Стоимость — по типовым регистрам стоимости (аренда, тарифные сетки).
- Обязательна связка с релизом 3 (без календаря занятости экономика бессмысленна).
