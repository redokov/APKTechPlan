# E2E веб-клиент — чек-лист (design §11 «E2E веб-клиент»)

Задача A12 (авторинг артефактов). Прогон — фаза B7, днём, публикация Apache.

**Окружение:**

- База: `dev_erpapk_demo` (сервер `localhost`), расширение «ПланированиеТехникиАПК» подключено и применено (UpdateDBCfg).
- Веб-клиент через Apache (если база опубликована; иначе — тонкий клиент как fallback, отметить в «Факт»).
- Основной пользователь: «Администратор (ОрловАВ)» с ролями `Тх_Чтение`, `Тх_Редактирование`.
- Для секции «Без ролей»: отдельный тестовый пользователь БЕЗ ролей `Тх_Чтение`/`Тх_Редактирование` (создаётся в B8).
- Устойчивые имена: подсистема `Тх_ПланированиеТехники` (синоним «Планирование техники»); команды навигации — «Планы технических ресурсов», «Коэффициенты пересчёта работ», «Дефицит техники»; команды действий — создание документа «План технических ресурсов», «Заполнение коэффициентов», «Расчет дефицита».

Заполнение: колонки «Факт» и «Статус» — при прогоне (B7). Статус: ☑ pass / ☒ fail / ☐ не проверялось.

## Замер NFR-002 (отдельная секция фиксации результатов)

Выполняется на тестовом наборе NFR-002 (генерация — `scripts/gen_nfr002_dataset.py`, создаётся в B7).
Критерии из design: расчёт + отчёт ≤ 30 с; автозаполнение коэффициентов одной работы ≤ 5 с.

| Метрика | Критерий | Замер 1 | Замер 2 | Замер 3 | Вердикт |
|---------|----------|---------|---------|---------|---------|
| Расчёт дефицита + открытие отчёта | ≤ 30 с | | | | |
| Формирование отчёта с фильтрами | ≤ 30 с | | | | |
| Автозаполнение коэффициентов по одной работе | ≤ 5 с | | | | |

Условия замера: база `dev_erpapk_demo`, веб-клиент Apache (или тонкий клиент — указать), пользователь «Администратор (ОрловАВ)», параметры расчёта по методике NFR-002. Каждый замер — на «холодном» и «тёплом» сеансе не обязателен; минимум 3 прогона, в таблицу — фактические значения.
