# Idea: Редизайн «Планирования техники АПК» — расчёт потребности по техкартам

> Status: captured
> Created: 2026-10-09
> Source: docs/redesign-prompt-2026-10-09.md (самодостаточный промт пользователя) + ответы пользователя в чате

## Raw Idea

Расширение «ПланированиеТехникиАПК» (CFE, префикс Тх_) для ЕРП АПК устроено неверно:
нетипизированные реквизиты форм и объектов, рантайм-баг, дубли синонимов, и главное —
план работ заполняется вручную вместо формирования ПО ДАННЫМ ПРОВЕДЁННЫХ технологических
карт (АпкТехнологическиеКартыНаПоле). Перепроектировать: конкретные типы everywhere,
контроль совместимости сцепки, обработка «Формирование плана работ техники»
(потребность в разрезе МОДЕЛЕЙ vs доступность по подразделениям из
Документ.АпкПланТехническихРесурсов), пользователь корректирует результат.

## Problem Space

- Техкарты планируют работы до моделей техники, но не до конкретных ТС; потребность
  хозяйства не сопоставляется с доступной техникой подразделений.
- Generic-составные типы реквизитов делают формы непроходимыми для НТТ/Vanessa и
  неудобными для пользователей («Выбор типа данных» в UI).
- Регистр Тх_КоэффициентыПересчетаРабот падает в рантайме при открытии записи
  (вызов несуществующего метода ИмяСправочникаМоделейСХТехники).
- Дубли синонимов: отчёт vs регистр «Дефицит техники»; наш документ vs
  АпкПланТехническихРесурсов «План технических ресурсов».

## Target Users

- Агроном-планировщик (формирует и корректирует план потребности);
- Собственник/топ-менеджер агрохолдинга (отчёт о дефиците);
- Обычный пользователь ИБ «Агроном» (правовые тесты ролей Тх_).

## Current Alternatives

- Ручное заполнение документа Тх_ПланТехническихРесурсов по конкретным ТС (нынешний
  релиз 001) — медленно, не связано с техкартами.
- Типовой АПК: Документ.АпкПланТехническихРесурсов (распределение ТС по подразделениям) —
  не считает потребность и не сравнивает с техкартами.

## Desired Outcome

План потребности в технике формируется автоматически из проведённых техкарт за период
(с учётом подразделения выращивания), в разрезе моделей техники и прицепных устройств,
с коэффициентами замещения по паспортным реквизитам моделей; сравнивается с доступной
подразделению техникой; пользователь правит результат. Все реквизиты типизированы,
сцепка контролируется, дубли синонимов устранены.

## Possible Directions

### Direction A: Эволюционный редизайн (ВЫБРАНА)

- **Description:** каркас объектов сохраняем (документ, регистры, отчёт, роли),
  ретайпируем реквизиты, документ переосмысляем как результат расчёта («Потребность
  в технике»), добавляем новую обработку, регистр Тх_КоэффициентыПересчетаРабот удаляем.
- **Pros:** без миграций, переиспользование форм/ролей/сценариев 01–02, скорость.
- **Cons:** внутренние имена остаются ТС-ориентированными (задокументировать синонимами).
- **Risks:** смешение старой/новой семантики в одном документе — снять чисткой форм.

### Direction B: Чистый лист

- **Description:** старые Тх_-объекты к удалению, новые объекты под новую онтологию.
- **Pros:** чистые имена. **Cons:** потеря наработок, дольше, против «нет миграций».
- **Risks:** ломка тестов 01–02. Отклонена пользователем.

### Direction C: Только гигиена (типизация+баг+синонимы, без обработки)

- Отброшена: не выполняет главную миссию (формирование по техкартам).

## Constraints

- Внутренние имена объектов НЕ меняем — только синонимы (нет миграций) [решено].
- Платформа 8.5.4.1683, CFE поверх ЕРП+АПК, база dev_erpapk_demo.
- Не трогать чужое расширение «Расширение_АПК» и VAExtension.
- Межподразделенческие замены (расстояния, трал, спецразрешения) — вне релиза 1.
- Правовые тесты — только на обычном пользователе ИБ («Агроном»), не на админе.

## Signals of Value

- Периодические данные годовых планов АПК 2014–2015 в демо-базе готовы для проверки расчёта.
