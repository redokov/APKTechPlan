# Feature: Анализ дефицита техники (по технологическим картам)

> Status: Approved (ночной прогон по standing-инструкции; ревью утром)
> Source: docs/digest-apk-techplanning.md, docs/digest-apk-objects.md, docs/product-reference-screens.md, C:/MyProjects/MyTasks/ПрезентацияПланированияТехники.md
> Last Updated: 2026-10-07

## Overview

Расширение (CFE) для «1С:ERP АПК 2.5», которое добавляет отсутствующий в типовом
функционале количественный анализ дефицита техники: агроном-планировщик формирует
технологические карты на поле (типовой механизм), после чего система сопоставляет
потребность в сменах по моделям техники с доступным парком подразделений (с учётом
взаимозаменяемости моделей через коэффициенты пересчёта) и выводит отчёт
«Дефицит техники» — сколько смен не хватает по подразделению/периоду/работе/модели.

Продукт состоит из трёх новых объектов: регистр сведений «Коэффициенты пересчёта
работ» (Период + Работа + Модель техники → коэффициент, автозаполнение
пропорционально мощности моделей), документ «План технических ресурсов»
(доступность техники подразделения по сценарию: три ТЧ с детализацией до конкретных
транспортных средств и признаком «Принят») и отчёт «Дефицит техники».

## Business Context

- **Problem:** В техкарте на поле для каждой работы указывается одна конкретная модель
  техники. Типовой АПК не позволяет сопоставить потребность по техкартам с фактическим
  парком разных хозяйств холдинга, пересчитать объём работы на взаимозаменяемую
  технику и получить отчёт о дефиците (объекты «Дефицит техники»/«Занятость техники»
  в составе АПК 2.5 отсутствуют — подтверждено разбором исходников).
- **Users:** агрономы-планировщики (заполнение коэффициентов, анализ отчёта),
  менеджеры парка / начальники бригад (заполнение планов техресурсов), собственники
  и топ-менеджеры агрохолдинга (потребители отчёта), администраторы (роли).
- **Value:** раннее выявление дефицита техники в сменах до начала сезона — обоснованные
  решения о переброске техники между хозяйствами, аренде или закупке; снижение потерь
  урожайности из-за «техника не там и не в то время».
- **Success signal:** пользователь по заполненным техкартам и планам техресурсов за один
  запуск отчёта получает количественный дефицит в сменах по подразделению/работе/модели.

## Goals

- Дать способ задать взаимозаменяемость моделей техники по видам работ (коэффициенты
  пересчёта) с автоматическим начальным заполнением по мощности моделей.
- Дать способ задать доступный парк техники по подразделению на сценарий планирования
  с детализацией до конкретных единиц (транспортных средств) и признаком «Принят».
- Рассчитать и показать дефицит в сменах по подразделению/периоду/работе/модели.
- Не модифицировать типовые объекты 1С:ERP АПК (расширение, безопасное для обновлений).

## Non-Goals / Out of Scope

- Изменение сроков работ техкарт без их модификации (планы развития продукта).
- Виртуальная техника для оценки минимально необходимого количества.
- Диаграмма Гантта с проблемными периодами и видами работ.
- Расчёт дефицита прицепных устройств (прицепы в транспортных работах техкарт
  присутствуют, но их дефицит не считаем).
- Дефицит операторов/механизаторов (ручные работы без техники — вне расчёта).
- Календарь занятости, простоев и ремонтов конкретных ТС; учёт наёмной техники
  вне признака «Принят».
- Модификация типовых объектов конфигурации, изменение форм и кода типовых
  документов/справочников/регистров.
- Автоматический подбор замены техники и перепланирование техкарт.

## User Stories

### US-001: Ведение коэффициентов пересчёта работ

**As a** агроном-планировщик
**I want to** задать для вида работы коэффициенты пересчёта для разных моделей техники
(базовая модель = 1,00, аналоги — свои значения)
**So that** система знала, во сколько смен аналог выполнит объём базовой модели

**Acceptance Criteria:**
- [ ] По виду работы можно задать коэффициент для каждой модели техники за период.
- [ ] Для работы можно указать одну базовую модель (коэффициент 1,00).
- [ ] Автозаполнение создаёт строки для моделей с коэффициентами, вычисленными
      пропорционально мощности двигателя моделей; значения редактируются вручную.
- [ ] Дубли строк «одна работа + одна модель + один период» не допускаются.

### US-002: Ведение плана технических ресурсов

**As a** менеджер парка / начальник бригады
**I want to** указать, какая техника доступна подразделению по сценарию планирования,
с детализацией до конкретных транспортных средств и признаком «Принят»
**So that** расчёт дефицита учитывал реально доступный парк, а не абстрактные модели

**Acceptance Criteria:**
- [ ] В документе задаются Организация, Подразделение, Сценарий планирования.
- [ ] Документ содержит три табличные части: Основная техника, Оборудование, Автотранспорт.
- [ ] Строка ТЧ — конкретное транспортное средство (справочник Транспортные средства);
      в строке виден хоз. номер и модель ТС.
- [ ] У строки есть признак «Принят»; непринятые единицы не попадают в расчёт.
- [ ] Документ проводится и отражает доступность техники в системе.

### US-003: Отчёт о дефиците техники

**As a** руководитель / агроном-планировщик
**I want to** получить отчёт «Дефицит техники» — сколько смен не хватает по
подразделению, периоду, виду работы и модели техники
**So that** принять решение о переброске, аренде или закупке техники до начала работ

**Acceptance Criteria:**
- [ ] Отчёт показывает потребность в сменах (из техкарт) и доступные смены
      (из планов техресурсов с пересчётом по коэффициентам) в разрезе
      подразделение / период / вид работы / модель техники.
- [ ] Выводится итоговый дефицит «Не хватает смен»; строки без дефицита можно скрыть.
- [ ] Отчёт фильтруется по подразделению, периоду, виду работы, модели техники,
      организации и сценарию планирования.
- [ ] Строки, по которым коэффициент не задан, явно помечаются и не участвуют
      в пересчёте (не подменяются значением 1,00 молча).

### US-004: Разграничение доступа

**As a** администратор
**I want to** выдавать роли чтения и редактирования новых объектов отдельно
**So that** плановики видели данные, а редактировали — только уполномоченные

**Acceptance Criteria:**
- [ ] Пользователь без выданных ролей не видит новые объекты и отчёт.
- [ ] Роль «чтение» разрешает просмотр данных и отчёта, но не изменение.
- [ ] Роль «добавление/изменение» разрешает создание и правку коэффициентов
      и планов техресурсов.

### US-005: Навигация по продукту

**As a** пользователь
**I want to** находить новые объекты и отчёт в командном интерфейсе системы
**So that** не искать их по списку «Все функции»

**Acceptance Criteria:**
- [ ] Новые объекты собраны в отдельной подсистеме расширения.
- [ ] Команды создания планов техресурсов, ведения коэффициентов и отчёта
      «Дефицит техники» доступны из командного интерфейса этой подсистемы.

## Functional Requirements

### FR-001: Хранение коэффициентов пересчёта — Must Have

THE SYSTEM SHALL хранить коэффициенты пересчёта работ в регистре сведений
с измерениями «Период», «Работа» (вид работ), «Модель техники» и ресурсом
«Коэффициент пересчёта работы»,
SO THAT для любой пары «работа + модель» на дату известно отношение смен аналога
к сменам базовой модели.

### FR-002: Форма ведения коэффициентов — Must Have

WHEN пользователь с правом изменения открывает форму коэффициентов
THE SYSTEM SHALL показывать строки «Работа / Модель техники / Коэффициент пересчёта»
с отбором по периоду и допускать добавление, изменение и удаление строк,
SO THAT коэффициенты ведутся интерактивно (референс s02).

### FR-003: Базовая модель работы — Must Have

THE SYSTEM SHALL для каждой работы допускать единственную базовую модель техники
с коэффициентом 1,00,
SO THAT коэффициенты аналогов имеют точку отсчёта (хранение «основных моделей
тракторов» из презентации).

### FR-004: Автозаполнение коэффициентов по мощности — Must Have

WHEN пользователь запускает автозаполнение коэффициентов по работе
THE SYSTEM SHALL для базовой модели заполнить коэффициент 1,00, а для остальных
моделей — значения, вычисленные пропорционально мощности двигателя моделей
(реквизит «МощностьДвигателя» справочника «Модели с/х техники»),
SO THAT регистр наполняется стартовыми оценками без ручного ввода, которые затем
корректируются вручную.

IF у модели не заполнена мощность двигателя
THE SYSTEM SHALL не создавать для неё строку автозаполнения (или создавать
с явной пометкой незаполненности — уточняется в дизайне).

### FR-005: Документ «План технических ресурсов» — Must Have

THE SYSTEM SHALL предоставлять документ «План технических ресурсов» с реквизитами
шапки «Организация», «Подразделение», «Сценарий планирования»,
SO THAT доступность техники задаётся в контексте планового сценария и подразделения
(референс s03).

### FR-006: Табличные части парка с детализацией до ТС — Must Have

THE SYSTEM SHALL включать в документ «План технических ресурсов» три табличные
части — «Основная техника», «Оборудование», «Автотранспорт»,
WHEN пользователь добавляет строку
THE SYSTEM SHALL требовать выбор конкретного транспортного средства
(справочник «Транспортные средства»), показывать его хоз. номер (АпкХозНомер)
и модель (АпкМодель), а также давать признак «Принят» и комментарий,
SO THAT план отражает доступность до конкретных единиц техники (референс s04).

### FR-007: Учёт признака «Принят» — Must Have

IF у строки плана техресурсов признак «Принят» не установлен
THE SYSTEM SHALL исключать это транспортное средство из расчёта доступных смен,
SO THAT в расчёт попадает только подтверждённый парк.

### FR-008: Потребность в сменах из технологических карт — Must Have

WHEN формируется расчёт дефицита
THE SYSTEM SHALL агрегировать потребность в сменах из проведённых документов
«Технологические карты на поле» (табличные части механизированных и транспортных
работ) по измерениям «Сценарий планирования», «Организация», «Подразделение»,
периоду строки (ПериодНачала/ПериодОкончания), виду работы и модели техники,
SO THAT потребность считается на типовых данных без изменения техкарт.

### FR-009: Доступные смены из планов техресурсов — Must Have

WHEN формируется расчёт дефицита
THE SYSTEM SHALL вычислять доступные смены по моделям техники из проведённых
планов технических ресурсов (принятые ТС) для того же сценария, организации,
подразделения и периода,
SO THAT потребность и доступность сопоставимы в одном разрезе.

### FR-010: Пересчёт доступности через коэффициенты — Must Have

IF для работы доступна техника модели, отличной от требуемой моделью техкарты,
и для пары «работа + модель» задан коэффициент пересчёта
THE SYSTEM SHALL пересчитывать доступные смены этой модели в смены требуемой модели
умножением на коэффициент (коэффициент = отношение смен аналога к сменам базовой
модели для того же объёма работы),
SO THAT взаимозаменяемый парк закрывает потребность по другой модели.

### FR-011: Обработка отсутствующего коэффициента — Must Have

IF для пары «работа + доступная модель» коэффициент пересчёта не задан
THE SYSTEM SHALL не подставлять значение 1,00 по умолчанию, а исключить эту модель
из пересчёта доступности и явно пометить затронутые строки отчёта признаком
«коэффициент не задан»,
SO THAT пользователь видит, что доступность занижена из-за незаполненных
коэффициентов, а не получает молча неверный результат.

### FR-012: Расчёт дефицита — Must Have

THE SYSTEM SHALL по каждой комбинации «подразделение / период / вид работы /
модель техники» вычислять дефицит как разность «потребность смен − доступные смены
(с учётом пересчёта)» и выводить результат «Не хватает смен» при положительной
разности,
SO THAT дефицит выражен количественно в сменах (референс s05).

### FR-013: Структура отчёта «Дефицит техники» — Must Have

THE SYSTEM SHALL выводить отчёт с группировками «Подразделение», «Период (дата
начала, дата окончания)», «Вид работы», «Модель техники» и колонками: потребность
смен, доступно смен, «Не хватает смен» (плюс признак «коэффициент не задан»
по FR-011),
SO THAT результат читается в разрезе управленческих решений.

### FR-014: Фильтры отчёта — Must Have

THE SYSTEM SHALL позволять фильтровать отчёт по организации, подразделению,
сценарию планирования, периоду, виду работы и модели техники,
SO THAT отчёт применим как по холдингу, так и по одной бригаде.

### FR-015: Отображение только дефицитных строк — Should Have

THE SYSTEM SHALL позволять включать/выключать показ строк без дефицита
(по умолчанию — показывать только дефицит),
SO THAT отчёт не тонет в избыточных строках.

### FR-016: Подсистема и командный интерфейс — Must Have

THE SYSTEM SHALL размещать новые объекты (регистр коэффициентов, план техресурсов,
отчёт) в подсистеме расширения и обеспечивать доступ к их командам
(создание документа, ведение коэффициентов, открытие отчёта) из командного
интерфейса этой подсистемы,
SO THAT продукт обнаружим в интерфейсе системы.

### FR-017: Роли доступа — Must Have

THE SYSTEM SHALL предоставлять отдельные роли: «чтение» (просмотр коэффициентов,
планов техресурсов и отчёта) и «добавление/изменение» (создание и правка
коэффициентов и планов техресурсов) на новые объекты,
SO THAT доступ разграничен и не зависит от типовых ролей АПК.

### FR-018: Контроль дублей коэффициентов — Should Have

THE SYSTEM SHALL не допускать двух действующих записей коэффициентов с одинаковыми
«период + работа + модель техники»,
SO OTHERWISE отчёт не неоднозначен при выборе коэффициента.

## Non-Functional Requirements

### NFR-001: Usability

- Формы и отчёт следуют типовым паттернам интерфейса 1С:ERP АПК (русские синонимы,
  компоновка ТЧ как в референс-скриншотах s02–s05).
- Отчёт формируется без модальных окон и фоновых заданий, не требующих настройки.

### NFR-002: Performance

- Отчёт «Дефицит техники» на тестовом наборе объёма холдинга (10 организаций,
  50 подразделений, 1000 техкарт на поле / ~10 000 строк работ, 1000 транспортных
  средств, 3 сценария) формируется не дольше 30 секунд на серверной СУБД.
- Автозаполнение коэффициентов по одной работе (до 100 моделей) выполняется
  не дольше 5 секунд.

### NFR-003: Compatibility / Maintainability

- Расширение не модифицирует типовые объекты 1С:ERP АПК: проверка применимости
  расширения (db-cfe-admin) проходит без ошибок, отключение/удаление расширения
  не влияет на работу типовой конфигурации и её обновление.
- Все новые имена объектов — с префиксом продукта (см. D-008/Q-007).

### NFR-004: Security

- Пользователи без выданных ролей расширения не имеют доступа к новым объектам,
  данным и отчёту (проверяется под учётной записью без ролей).
- Новые роли не расширяют права на типовые объекты.

### NFR-005: Reliability

- Расчёт дефицита детерминирован: при неизменных исходных данных (техкарты, планы,
  коэффициенты) повторный запуск даёт тот же результат.
- Отсутствие данных (нет планов техресурсов / нет коэффициентов) не приводит
  к ошибке выполнения — отчёт формируется с явной пометкой таких строк.

## User Experience Notes

- Основной поток: заполнить коэффициенты (частично автозаполнением по мощности)
  → заполнить планы техресурсов по подразделениям → сформировать отчёт
  «Дефицит техники» → проанализировать «Не хватает смен».
- Пустые состояния: при отсутствии коэффициентов или планов техресурсов отчёт
  показывает потребность и явную пометку, что доступность не посчитана
  (не ноль и не ошибка).
- Признак «Принят» — простой чекбокс в строке ТЧ; подсчёт принятых единиц
  виден в форме документа.

## Constraints

- Продукт — только расширение (CFE) для 1С:ERP АПК 2.5 (платформа 8.5),
  установка без снятия типовой конфигурации с поддержки.
- Источник потребности — только типовые документы «АпкТехнологическиеКартыНаПоле»
  (в них хранятся модели техники, вид работ, периоды и смены; конкретные ТС
  в техкартах не хранятся).
- Детализация парка — только типовой справочник «ТранспортныеСредства»
  (АпкХозНомер, АпкМодель); связка «ТС ↔ подразделение» задаётся документом
  «План технических ресурсов», а не реквизитом справочника (типовые реквизиты
  подразделения у ТС помечены на удаление).
- Автозаполнение коэффициентов опирается на реквизит «МощностьДвигателя»
  справочника «АпкМоделиСХТехники»; для моделей автотранспорта мощности
  в типовых данных нет (см. Q-005).

## Decisions

### D-001: Продукт — расширение, типовые объекты не модифицируются

**Decision:** Продукт реализуется как расширение конфигурации (CFE) для
1С:ERP АПК 2.5; собственные новые объекты, без изменения типовых объектов,
форм и модулей.
**Reason:** требование поставки из презентации: не влияет на обновление основной
конфигурации; соответствует конвенциям проекта.
**Source:** прямая инструкция пользователя / презентация («Поставка»).
**Impacts:** все FR, NFR-003.

### D-002: Потребность — из документов «Технологические карты на поле»

**Decision:** Потребность в сменах агрегируется из ТЧ «МеханизированныеРаботы»
и «ТранспортныеРаботы» документа «АпкТехнологическиеКартыНаПоле» (модели техники,
вид работы, периоды строки, смены), по сценарию/организации/подразделению шапки.
**Reason:** это единственное типовое место, где плановые работы привязаны к технике;
конкретные ТС в техкартах не хранятся (раздел 7b дайджеста объектов).
**Source:** решённый факт пользователя.
**Impacts:** FR-008, Out of Scope.

### D-003: Доступность — новый документ «План технических ресурсов»

**Decision:** Доступность техники задаётся новым документом «План технических
ресурсов» (шапка: Организация, Подразделение, Сценарий планирования; ТЧ: Основная
техника / Оборудование / Автотранспорт; строка — конкретное ТС справочника
«Транспортные средства» с хоз. номером и признаком «Принят»).
**Reason:** типовой функционал не содержит календаря доступности парка по
подразделениям; референс s03–s04.
**Source:** решённый факт пользователя.
**Impacts:** FR-005, FR-006, FR-007, FR-009.

### D-004: Коэффициенты — новый регистр сведений с автозаполнением по мощности

**Decision:** Взаимозаменяемость моделей хранится в новом регистре сведений
(Период + Работа + Модель техники → коэффициент); автозаполнение вычисляет
коэффициенты пропорционально мощности двигателя моделей (базовая модель = 1,00),
значения редактируются вручную.
**Reason:** референс s02 и слайд «Поставка» («хранит основные модели тракторов
и может вычислить коэффициент пересчёта пропорционально мощности»).
**Source:** решённый факт пользователя.
**Impacts:** FR-001..FR-004, FR-010, FR-018.

### D-005: Дефицит измеряется в сменах, вывод «Не хватает смен»

**Decision:** Отчёт «Дефицит техники» сопоставляет потребность в сменах из техкарт
с доступными сменами (пересчитанными через коэффициенты) и выводит разность
«Не хватает смен» по подразделению/периоду/работе/модели.
**Reason:** референс s05; смена — натуральная единица плана техкарт.
**Source:** решённый факт пользователя.
**Impacts:** FR-008..FR-015.

### D-006: Функционал развития — вне объёма первой версии

**Decision:** Изменение сроков работ, виртуальная техника, диаграмма Гантта,
расчёт дефицита прицепных устройств — Out of Scope.
**Reason:** слайд «Развитие функционала» презентации — отдельные будущие версии.
**Source:** прямая инструкция пользователя.
**Impacts:** Out of Scope.

### D-007: Дефицит по основной технике и автотранспорту; оборудование — без пересчёта

**Decision:** В расчёте дефицита участвуют модели с/х техники (механизированные
работы) и модели автотранспорта (транспортные работы). ТЧ «Оборудование» плана
техресурсов ведётся и отображается в документе, но в пересчёт дефицита
оборудование в v1 не включается.
**Reason:** отчёт-референс содержит «Модель техники» без оборудования;
включение оборудования (навесного, сцепки) усложняет алгоритм (ЕдВСцепке)
без подтверждённой потребности.
**Source:** рекомендация ночного прогона (см. Q-005 — подтвердить утром).
**Impacts:** FR-006, FR-008, Out of Scope.

### D-008: Автономный статус требований

**Decision:** requirements.md помечен Approved в рамках ночного автономного
прогона по standing-инструкции пользователя («закончишь планировать — приступай
к разработке»); открытым вопросам присвоены Q-xxx с рекомендациями, они не
блокируют переход к дизайну, но подлежат ревью утром.
**Reason:** standing-инструкция; скилл разрешает фиксировать открытые вопросы
в артефакте.
**Source:** прямая инструкция пользователя.
**Impacts:** Status, Q-001..Q-007.

## Questions

### Q-001: Смен в день у доступного ТС

**Status:** open
**Why it matters:** от числа смен в день на единицу техники напрямую зависит величина
доступных смен и дефицита (FR-009, FR-012).
**Recommended:** Option A — 1 смена в день на ТС; параметр отчёта «смен в день»
(значение по умолчанию 1) как Could Have.
| Option | Answer | Choose this if... | Impact |
|--------|--------|-------------------|--------|
| A | 1 смена/день, параметр отчёта по умолчанию 1 | нужны простые предсказуемые расчёты | FR-009: смены = принятые ТС × дни периода × смен/день |
| B | Продолжительность смены из норм вида работы | хотим опираться на нормы АПК | сложнее, зависит от заполняемости норм |
| Custom | пользовательское значение | оба варианта не подходят | пересмотр FR-009 |

### Q-002: Разрез периодов в расчёте и отчёте

**Status:** open
**Why it matters:** строки техкарт имеют произвольные периоды (ПериодНачала/
ПериодОкончания); нужно определить, по каким интервалам агрегировать и как
группировать «Дата начала / Дата окончания» в отчёте (FR-008, FR-013).
**Recommended:** Option B — расчёт по интервалам строк техкарт (точность до
исходных данных), группировка в отчёте по календарным отрезкам (неделя/декада/
месяц — выбирается в отчёте).
| Option | Answer | Choose this if... | Impact |
|--------|--------|-------------------|--------|
| A | Только интервалы строк техкарт как есть | нужна максимальная точность | отчёт с рваными периодами, сложнее читать |
| B | Расчёт по строкам, группировка по календарным отрезкам | нужен читаемый отчёт | пересечение периодов распределяется по отрезкам (см. Q-006) |
| C | Только календарные отрезки (день/неделя/месяц) | простота важнее точности | потеря точности на границах периодов |
| Custom | пользовательское значение | — | пересмотр FR-008/FR-013 |

### Q-003: Строки плана техресурсов без конкретного ТС

**Status:** open
**Why it matters:** определить, можно ли указать доступность «модель + количество»
без выбора конкретных единиц (FR-006).
**Recommended:** Option A — только конкретные ТС; в v1 строки без ТС не допускаются.
| Option | Answer | Choose this if... | Impact |
|--------|--------|-------------------|--------|
| A | Только конкретные ТС | парк ведётся в справочнике ТС, нужна точность до госномеров | FR-006 остаётся строгим |
| B | Модель + количество как альтернатива | парк дублируется вне ТС | усложнение расчёта, риск расхождений |
| Custom | пользовательское значение | — | пересмотр FR-006 |

### Q-004: Семантика коэффициента пересчёта

**Status:** open
**Why it matters:** направление коэффициента определяет формулу пересчёта
(FR-010) и автозаполнение (FR-004). На референсе s02 аналог имеет 0,80 при
базовой 1,00.
**Recommended:** Option B — коэффициент = «во сколько раз больше/меньше смен
нужно аналогу»: 0,80 означает, что аналог выполнит объём базовой модели за 0,8
смены (аналог производительнее); доступные смены пересчитываются делением
на коэффициент... — формула фиксируется в дизайне, на уровне требований
принимается только семантика «отношение смен аналога к сменам базовой модели».
| Option | Answer | Choose this if... | Impact |
|--------|--------|-------------------|--------|
| A | Коэффициент = производительность относительно базовой (0,80 = медленнее на 20%) | интуиция «доля производительности» | формула FR-010 — умножение |
| B | Коэффициент = отношение смен аналога к сменам базовой (0,80 = быстрее) | согласуется с примером s02 (базовая 1,00, аналог 0,80 при большей мощности) | формула FR-010 — деление/умножение, фиксируется в design |
| Custom | пользовательское значение | — | пересмотр FR-004/FR-010 |

### Q-005: Участие оборудования и автотранспорта в расчёте дефицита

**Status:** open
**Why it matters:** определяет полноту расчёта и сложность (FR-008, D-007):
в техкартах есть модели оборудования (ЕдВСцепке) и автотранспорта; мощности
двигателя у моделей автотранспорта/оборудования в типовых данных нет.
**Recommended:** Option B — v1 считает дефицит по основной технике
(механизированные работы) и автотранспорту (транспортные работы, без пересчёта
по коэффициентам — только модель в модель); оборудование — только ведение
в плане техресурсов, без расчёта.
| Option | Answer | Choose this if... | Impact |
|--------|--------|-------------------|--------|
| A | Только основная техника | минимальный объём, быстрее выход | транспортные работы вне отчёта |
| B | Основная техника + автотранспорт (модель в модель) | покрывает оба вида работ техкарт | коэффициенты для автотранспорта — Could Have |
| C | Все три вида, включая оборудование | полный охват | нужны коэффициенты для оборудования; сцепки усложняют алгоритм |
| Custom | пользовательское значение | — | пересмотр FR-008/D-007 |

## Glossary

- **Техкарта на поле:** типовой документ «АпкТехнологическиеКартыНаПоле» — план
  работ по полю (механизированные, транспортные, ручные работы).
- **Модель техники:** элемент справочников «АпкМоделиСХТехники» /
  «АпкМоделиАвтотранспорта» и т.п.; в техкартах хранятся только модели.
- **ТС (транспортное средство):** элемент справочника «ТранспортныеСредства» —
  конкретная единица парка (хоз. номер АпкХозНомер, модель АпкМодель).
- **Коэффициент пересчёта:** отношение смен модели-аналога к сменам базовой модели
  для одного вида работы (базовая = 1,00).
- **План технических ресурсов:** новый документ — доступный подразделению парк
  по сценарию планирования, до конкретных ТС, с признаком «Принят».
- **Дефицит:** положительная разность «потребность смен − доступные смены»
  по подразделению/периоду/работе/модели; вывод «Не хватает смен».
- **Смена:** плановая единица работы техники в техкартах (ресурс «Смен»).
