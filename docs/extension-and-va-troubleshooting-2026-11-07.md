# Почему работа с расширением «не получалась» — разбор 2026-11-07

Короткий ответ: ломалось не расширение, а **три вещи вокруг него**. Каждая давала
симптом «изменения не применяются» / «вишу часами».

---

## 1. Зависание дизайнера: забыт `/DisableStartupDialogs`

Без этого ключа `1cv8.exe DESIGNER` при любой проблеме (неверный параметр,
не та база, не тот пользователь) открывает **модальное окно** и висит до
ручного клика. Вызов из bash выглядит как «Command aborted» после таймаута,
в логах — пусто. Именно так сгорело 4 часа.

**Правило:** любой batch-вызов дизайнера — только с `/Out"<файл>" /DisableStartupDialogs`.

## 2. Авторизация: способ передачи `/N"Имя (Отчество)"` через Python

Пользователь ИБ — `Администратор (ОрловАВ)`: пробел + скобки. Варианты,
которые НЕ работают:

| Способ | Что уходит в 1С | Ответ платформы |
|---|---|---|
| `subprocess([..., '/N"user"'])` | `/N\"user\"` (list2cmdline экранирует кавычки) | «Пользователь ИБ не идентифицирован» |
| `subprocess([..., '/Nuser'])` | токен с пробелом внутри | «Ошибка в параметрах командной строки» |
| `subprocess([..., '/N', user])` | `/N user` (раздельно) | «Ошибка в параметрах командной строки» |

Работает: **готовая строка командной строки** (без list2cmdline), ключи склеены
со значениями: `/S"localhost/dev_erpapk_demo" /N"Администратор (ОрловАВ)"`.
Реализация — `scripts/designer_ps.py`.

> Почему у `db-load-xml.ps1` получалось: он собирает аргументы сам и на Windows
> отдаёт их одной строкой (`db-cfe-admin.py:run_v8`, ветка `os.name == "nt"`).

## 3. Настоящий блокер тестов: не компилировался общий модуль

Коммит `e548f7f` (S1 ночного прогона) поставил управляемую блокировку **до**
создания набора записей:

```bsl
Элемент.ИсточникДанных = НаборЗаписей;   // ← НаборЗаписей ещё не существует
...
НаборЗаписей = РегистрыСведений.Тх_ДефицитТехники.СоздатьНаборЗаписей();
```

Результат в клиенте:
`Ошибка инициализации модуля: ...Тх_ТехникаСервер... Переменная не определена (НаборЗаписей)`.

Дополнительно свойство `ЭлементБлокировкиДанных.ИсточникДанных` принимает только
`РезультатЗапроса | ТабличнаяЧасть | ТаблицаЗначений` — **набор записей туда
передать нельзя** (проверено по bsl-platform-context).

**Исправлено** (`Тх_ТехникаСервер`, блок «T-LOCK-V2»): блокировка ставится по
значениям измерений через `Элемент.Установить("СценарийПланирования" | "Организация"
| "Подразделение", ...)`.

Важно: `/CheckModules -Extension` и `/CheckConfig -ExtendedModulesCheck` **эту
ошибку не показали** (вернули «Синтаксических ошибок не обнаружено» и только
предупреждения «Возможно ошибочное свойство»). Единственный надёжный гейт —
фактический запуск клиента.

## 4. Зависание на `ПодключениеTestClient:порт <48000>`

Не расширение. Причина — **локальная копия EPF** `tests/vanessa/vanessa-automation-single.epf`
(22.5 МБ, md5 `ac12d345…`): менеджер стартует, TCP встаёт, но хендшейк не
завершается. Эталонный EPF (22.6 МБ, md5 `7775219528082115c21df695f53e321e`)
из `C:\Program Files\OneScript\lib\vanessa-automation-single\` работает.

`scripts/run_va_feature.py` теперь берёт EPF из этого пути (переопределяется
переменной окружения `VA_EPF`).

## 5. Порядок применения изменений расширения

```
pre_load_validate.py → bsl-ls → db-load-xml.ps1 (Full, -Extension, -UpdateDB)
  → прочитать свежий $TEMP/db_load_xml_*/load_log.txt (cp1251!)
  → при структурных правках: повторить /UpdateDBCfg
  → kill 1cv8c/1cv8 → пауза ~5 мин (кэш rphost)
  → прогон feature
```

Batch `/UpdateDBCfg -Extension` не всегда создаёт новую генерацию: если после
прогона поведение старое — повторить `/UpdateDBCfg` (через `scripts/designer_ps.py`)
и дать кэшу остыть.

## 6. Проверка, что код реально в базе (round-trip)

```
python scripts/load_extension.py
rm -rf $TEMP/rt_dump_apktechplan && python scripts/dump_extension.py
grep -c "T-LOCK-V2" $TEMP/rt_dump_apktechplan/CommonModules/Тх_ТехникаСервер/Ext/Module.bsl
```

Маркер в выгрузке = код доехал до базы. Без такой проверки «загрузилось успешно»
ничего не доказывает.
