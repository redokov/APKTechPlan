# Развёртывание расширения «ПланированиеТехникиАПК» в новой информационной базе

Инструкция для администратора. Описано, что установить, в каком порядке и как
проверить, что всё работает. Всё, что нужно для работы расширения, — в разделе 1;
контур автопроверок (нужен только разработчикам) — в разделе 10.

---

## 1. Что нужно установить и подготовить

| Что | Требование | Зачем |
|---|---|---|
| Платформа «1С:Предприятие» | 8.5.4 (проверено на 8.5.4.2028). Минимум для этого расширения — не ниже 8.3.27: таков режим совместимости расширения | Среда исполнения |
| Вариант работы | серверный (кластер) или файловый — любой. Серверный предпочтителен для нескольких пользователей | Размещение базы |
| Клиентские лицензии | по числу одновременно работающих пользователей; серверная лицензия — при серверном варианте | Доступ пользователей |
| Конфигурация-хозяин | та конфигурация, в которой есть подсистема АПК (объекты перечислены в разделе 2) | Расширение — дополнение к ней, само по себе не работает |
| Права | полные права администратора в базе | Добавление расширения и обновление конфигурации базы данных |
| Комплект расширения | **один файл** `ПланированиеТехникиАПК.cfe` | Это и есть поставочный комплект: расширение передаётся файлом и ставится на новую базу одним действием |

Что внутри файла: язык «Русский», подсистема «Планирование техники»,
две роли, общий модуль расчёта, перечисление видов техники, отчёт о дефиците,
две обработки (расчёт дефицита и формирование плана работ) и два регистра
сведений (дефицит техники, момент расчёта). Имя расширения —
`ПланированиеТехникиАПК`, префикс имён — `Тх_`, назначение — «Дополнение»,
версия `1.0.0.1`. Файл самодостаточен: распаковывать нечего, папки с файлами
рядом не нужны.

**Проверочных объектов в поставке нет и быть не должно** (общий модуль
автопроверок, запускатор проверок, константа-маркер тестовой базы, регистр
реестра проверочных объектов, обработки подготовки данных и запуска сценариев).
Подробнее — раздел 9.

---

## 2. Обязательные объекты конфигурации-хозяина

Расширение читает эти объекты. Если какого-то из них нет, расширение не
применится или расчёт не заработает.

| Вид | Объект |
|---|---|
| Справочник | `ТранспортныеСредства` — с реквизитами `АпкМодель`, `АпкТипТС`, `АпкХозНомер` |
| Справочник | `АпкМоделиСХТехники`, `АпкМоделиСХОборудования`, `АпкМоделиАвтотранспорта`, `АпкМоделиПрицепов` |
| Справочник | `АпкСценарииПланирования` |
| Справочник | `ВидыРаботСотрудников` |
| Документ | `АпкПланТехническихРесурсов` |
| Регистр сведений | `АпкИсторияТранспортныхСредств` |
| Регистр накопления | `АпкМеханизированныеРаботыПоГодовомуПлану`, `АпкТранспортныеРаботыПоГодовомуПлану` |
| Перечисление | `АпкТипыТС` |

Собственных заимствованных объектов из конфигурации-хозяина у расширения нет:
оно расширяет конфигурацию составом, а не правкой чужих модулей. Поэтому
обновление конфигурации-хозяина расширение не блокирует, но версия
конфигурации должна содержать перечисленные объекты.

---

## 3. Шаг 1. Создать новую информационную базу

Вариант «серверный»: в кластере создать новую информационную базу (например,
`apk_plan_prod`) и добавить её в список баз.

Вариант «файловый»: в окне запуска «1С:Предприятие» — «Добавить» → «Создание
новой информационной базы» → «На данном компьютере или в локальной сети» →
указать пустую папку.

После создания база пустая: в ней нет ни конфигурации, ни данных.

---

## 4. Шаг 2. Загрузить конфигурацию-хозяина

1. Открыть базу в Конфигураторе под администратором.
2. «Конфигурация» → «Открыть конфигурацию» → «Загрузить конфигурацию из файла»
   (файл `*.cf`, полученный от поставщика конфигурации), либо восстановить базу
   из выгрузки поставщика (`*.dt`).
3. «Конфигурация» → «Обновить конфигурацию базы данных» (принять изменения).
4. Проверить, что база открывается в режиме «1С:Предприятие» и в ней есть
   объекты из раздела 2.

Если база с конфигурацией уже есть (например, копия рабочей), шаг 2 пропускается.

---

## 5. Шаг 3. Добавить расширение из файла

1. В Конфигураторе: «Конфигурация» → «Расширения конфигурации».
2. «Добавить» → в диалоге выбрать **файл** `ПланированиеТехникиАПК.cfe`
   (тип файла — «Расширение конфигурации (*.cfe)»).
3. Убедиться, что в списке появилось расширение `ПланированиеТехникиАПК`,
   состояние — «Активно», назначение — «Дополнение», версия `1.0.0.1`.
4. Имя и назначение менять не требуется.

Если вместо файла передали папку с файлами расширения (29 файлов), порядок тот
же, но в диалоге «Добавить» выбирается папка, а затем выполняется
«Загрузить из файлов». Для обычной передачи достаточно файла `*.cfe`.

---

## 6. Шаг 4. Применить расширение к базе данных

Это отдельное обязательное действие: добавление расширения в список ещё не
делает его работающим.

1. В списке расширений нажать «Применить» (или «Обновить конфигурацию базы
   данных» с выбранным расширением).
2. Дождаться сообщения об успешном применении. При первом применении в базе
   создаются собственные таблицы расширения (регистры «Дефицит техники» и
   «Момент расчёта»).
3. Перезапустить сеансы пользователей, чтобы они увидели новый раздел.

Важно: если после загрузки файла не применить расширение, изменения лежат
«в ожидании» и в базе не работают — признак этого: раздел в интерфейсе не
появляется, расчёт не находит новых объектов.

---

## 7. Шаг 5. Назначить роли пользователям

Расширение даёт две роли:

| Роль | Что даёт |
|---|---|
| `Тх_Чтение` | просмотр раздела «Планирование техники», отчёта о дефиците, плана работ |
| `Тх_Редактирование` | расчёт дефицита, формирование плана работ, восстановление данных |

Порядок: «Администрирование» → «Пользователи» → выбрать пользователя →
«Права» → установить нужные роли → записать. Роли по умолчанию расширение не
назначает: без них раздел не виден.

---

## 8. Шаг 6. Проверка результата

| Что проверить | Ожидаемый результат |
|---|---|
| Раздел интерфейса | появился раздел «Планирование техники» |
| Обработки | «Расчёт дефицита» и «Формирование плана работ техники» открываются |
| Отчёт | «Дефицит техники» открывается; при отсутствии данных в теле отчёта видно «Данных нет» |
| Регистры | в конфигураторе видны два регистра сведений расширения |
| Расчёт | при наличии данных в справочниках и регистрах расчёт дефицита выполняется, результат виден в отчёте |
| Права | у пользователя без ролей `Тх_*` раздела не видно |

Если отчёт открылся пустым и без строки «Данных нет», значит применено не то
расширение или применено старое — см. раздел 11.

## 9. Чего в промышленной базе нет и почему

| Нет | Почему |
|---|---|
| Константа «Тестовая база» и её проверки | маркер нужен только для запрета тестовых записей в тестовой базе; в поставляемом расширении его нет |
| Общий модуль автопроверок, запускатор проверок, регистр реестра проверочных объектов | это инструменты разработчика; они не должны ездить в промышленность |
| Обработки подготовки тестовых данных и запуска сценариев проверки | то же: нужны только в контуре проверки |
| `OneScript`, «Vanessa Automation», служебные программы на Python | это окружение автопроверок, а не работы расширения |

Практический смысл: в промышленной базе нельзя случайно запустить автопроверки
и нельзя записать тестовые данные — нужных для этого объектов там физически нет.

---

## 10. Что дополнительно нужно только для контура автопроверок (разработка)

Ставится на отдельную тестовую базу, а не рядом с рабочей:

| Что | Назначение |
|---|---|
| Платформа 8.5.4, тонкий клиент, `1cv8c.exe` | запуск тестового клиента |
| `OneScript` | исполнение «Vanessa Automation» |
| «Vanessa Automation» (однофайловая сборка `vanessa-automation-single.epf`) | проигрывание сценариев проверки |
| Служебные программы на Python из папки `scripts` | загрузка расширения, выгрузка и сверка, запуск автопроверок |
| Отдельная база с расширением, полный комплект (с проверочными объектами) | без проверочных объектов автопроверки запустить нельзя |

Для работы расширения в промышленной базе этот раздел не нужен.

## 11. Частые затруднения

| Сообщение / признак | Причина и что делать |
|---|---|
| «Расширение с таким именем уже существует» | расширение уже добавлено: сначала удалить старое (или обновить его), затем загрузить заново |
| «Обнаружено пересечение внутренних идентификаторов с расширением конфигурации …» | рядом уже есть другое расширение с теми же внутренними идентификаторами объектов (в нашем случае так бывает при копировании объекта из одного расширения в другое). Лечится выдачей новых идентификаторов объектам нового расширения |
| Расширение загрузилось, но раздел не появился | не выполнено «Применить» (раздел 6), либо пользователю не назначены роли (раздел 7) |
| При применении ошибка про отсутствующий объект | в конфигурации-хозяине нет объекта из раздела 2 — нужна конфигурация с подсистемой АПК нужной версии |
| Ошибка про несовместимость режима | платформа старше не требуется, но младше 8.3.27 — недостаточно |
| Отчёт пуст и без строки «Данных нет» | применялось другое (старое) расширение; проверить версию и повторить раздел 6 |
| В командной строке «Файл не обнаружен 'C:\Program'» | путь с пробелом передан без кавычек: ключи `/Execute"…"` и `/Out"…"` должны быть склеены с кавычками |
| «Файл не является файлом расширения конфигурации» | выбран не тот файл: нужен `*.cfe`, а не `*.cf` конфигурации и не папка с файлами |
| Файл расширения не принимается из-за версии платформы | файл собран на платформе новее той, что стоит на целевой базе: обновить платформу либо передать файл, собранный на нужной версии |
| Командный запуск Конфигуратора «висит» | не указан ключ отключения стартовых диалогов `/DisableStartupDialogs` |

## 12. Как получается сам файл поставки (для того, кто собирает поставку)

Файл `ПланированиеТехникиАПК.cfe` — это выгрузка **поставочного** состава
расширения, а не рабочего: проверочных объектов в нём быть не должно. Порядок
один раз на версию:

1. Собрать поставочный профиль из исходников: `scripts/make_prod_cfe.py`
   (создаёт папку `dist\ПланированиеТехникиАПК` — рабочее дерево без шести
   проверочных объектов; `--check` подтверждает, что содержимое совпадает с
   рабочим деревом).
2. Загрузить этот профиль в базу с конфигурацией-хозяином и применить его.
3. В Конфигураторе: «Расширения конфигурации» → выделить расширение →
   «Сохранить в файл» → `ПланированиеТехникиАПК.cfe`.
4. Проверить полученный файл на чистой базе по разделам 3–8 этой инструкции.

Файл `*.cfe` в истории версий проекта не хранится (двоичный, зависит от версии
платформы); он передаётся как файл поставки вместе с этой инструкцией.

## 13. Автоматизация установки (для повторяемых развёртываний)

Если развёртывание нужно повторять, у нас для этого есть служебные программы:
`scripts/load_extension.py` (загрузка расширения из папки файлов и обновление
конфигурации базы данных) и `scripts/pre_load_validate.py` (быстрая проверка
файлов расширения до загрузки, ловит типичные ошибки разбора). Если ставится
файл `*.cfe`, командная загрузка выполняется ключом
`/LoadCfg "путь\ПланированиеТехникиАПК.cfe" -Extension ПланированиеТехникиАПК`.
При командных запусках соблюдать две вещи: кириллические значения передавать из
файла, а не из командной строки, и после загрузки перезапускать сеанс
Конфигуратора, который применяет изменения, иначе применяется старая версия.

---

## 14. Порядок обновления расширения в дальнейшем

1. Получить новый файл `ПланированиеТехникиАПК.cfe` новой версии (собран из
   поставочного состава, без проверочных объектов).
2. В Конфигураторе: «Расширения конфигурации» → выделить расширение →
   «Заменить файл расширения» (при необходимости сначала «Удалить», затем
   «Добавить» из нового файла).
3. «Применить» и дождаться успеха.
4. Проверить раздел 8.
5. Данные регистров расширения при обновлении сохраняются; при полном удалении
   расширения — теряются (это штатное поведение платформы).
